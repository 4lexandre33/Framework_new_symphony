ETAPA 88 — DESKTOP / STEAM PRODUCTION READINESS
=================================================

OBJETIVO
--------
Certificar a Layer 1 como aplicação desktop Tauri pronta para release e
empacotamento Windows/Steam, sem modificar o runtime já certificado nas
Stages 85–87.

PRÉ-REQUISITOS REAIS
--------------------
- ETAPA86_AUTOMATED_PASS.json = PASS / 0 violations.
- ETAPA87_AUTOMATED_PASS.json = PASS / 0 violations.

Não existe bootstrap/backfill de ZIPs. A Stage 88 executa diretamente sobre a
branch remota certificada.

CONTRATOS CERTIFICADOS
----------------------
- package/Tauri/Cargo version 0.1.0 coerentes;
- productName projeto1 / identifier com.projeto1.game;
- frontendDist ../dist e beforeBuildCommand oficial npm run build;
- CSP explícita e withGlobalTauri=false;
- bundle ativo e icons existentes;
- janela desktop 1280x720, resizable, transparente/borderless/always-on-top
  tratados como configuração intencional existente;
- DPR limitado e resize listener removível;
- blur/visibility/pointer-lock limpam estado de input;
- windows_subsystem=windows somente em release;
- SteamState inicializa uma vez no host e encerra em RunEvent::Exit;
- steam_appid.txt=480 existe somente como contrato de desenvolvimento;
- o AppID 480 não é adicionado aos resources do bundle;
- Cargo default feature steam permanece explícita;
- Cargo.toml não pode permanecer alterado após a certificação.

CERTIFICAÇÃO NATIVA
-------------------
Linux:
1. preflight completo Stage 88;
2. Tauri release real com --no-bundle;
3. executável src-tauri/target/release/projeto1 deve existir;
4. SHA-256/tamanho do executável são gravados;
5. Cargo.toml é snapshotado antes do Tauri CLI e restaurado byte-a-byte depois;
6. hash final do manifest deve ser idêntico ao hash original.

Windows:
1. checkout do MESMO github.sha imutável certificado no Linux;
2. download de ETAPA88_RELEASE_SMOKE_EVIDENCE.json via GitHub Actions artifact;
3. Vite production build;
4. Tauri release real com --bundles nsis;
5. projeto1.exe deve existir;
6. instalador NSIS .exe deve existir;
7. SHA-256/tamanho de executável e installer são gravados;
8. Cargo.toml é restaurado byte-a-byte caso o Tauri CLI normalize o arquivo.

NORMALIZAÇÃO DO TAURI CLI
-------------------------
A primeira execução GitHub desta revisão compilou o release Linux com sucesso,
mas mostrou que o Tauri CLI normaliza src-tauri/Cargo.toml. A Stage 88 trata
isso como mutação transitória de ferramenta: os smokes preservam os bytes
originais, restauram o arquivo após o build e registram explicitamente
cargoManifestMutatedByTauri/cargoManifestRestored nas evidências.

TOOLCHAIN
---------
A certificação oficial usa Rust 1.97.0 e CARGO_BUILD_JOBS=1 no GitHub Actions.
Isso é política de certificação reproduzível, não alteração do Cargo.toml.

AUTORIDADE
----------
.github/workflows/stage88-production.yml

A Stage 88 só termina PASS após Linux release + Windows NSIS reais e commit das
evidências ETAPA88_* pelo GitHub Actions.

REVISION 2.0.2 — IMMUTABLE CROSS-RUNNER CERTIFICATION
------------------------------------------------------
Linux e Windows certificam exatamente o mesmo github.sha.

A evidência Linux não é mais commitada no meio do workflow. Ela é transferida
ao runner Windows por actions/upload-artifact + actions/download-artifact.
Somente o job Windows final publica o commit de certificação Stage 88.

A concurrency usa cancel-in-progress=true: uma revisão Stage 88 nova invalida e
cancela certificações obsoletas, impedindo evidência de SHA antigo na branch.

A auditoria normaliza CRLF para LF antes dos checks de texto. Isso elimina
diferenças artificiais entre checkout Linux e Windows sem relaxar nenhum
contrato semântico.
