O QUE O AUDITOR VALIDA

1. BASELINE COMPATIBILITY
Os 23 módulos certificados na v1 precisam continuar presentes.

Identidade estrutural protegida:
- key;
- layer/category;
- firstParty/bootstrapped;
- primary capabilityId;
- engine ownership path;
- plugin ownership.

Arquivos declarados na baseline não podem desaparecer:
- contracts;
- tokens;
- native files;
- tests;
- extra files.

É permitido adicionar novos contracts/tests/arquivos a um módulo existente.

2. EXTENSIBILIDADE
Novos módulos canônicos são permitidos.

Exemplo futuro válido:

game.weather

Após registro oficial no module-map, contracts/tokens/plugin/public/internal e
demais requisitos precisam existir.

A baseline v1 continua certificando que os 23 módulos originais não sumiram,
mas NÃO exige que a contagem atual continue sendo 23.

Portanto:

23 = quantidade capturada na Layer 1 Baseline v1

NÃO:

23 = limite permanente da engine

3. REGISTRY INTEGRITY
Para todos os módulos canônicos atuais, incluindo capacidades futuras:

- unique module key;
- unique primary capability;
- unique owned capability/token;
- functional layer inteira positiva e não duplicada;
- runtime layer null;
- firstParty = true;
- bootstrapped = true;
- engine root = src/engine/<key>;
- public = src/engine/<key>/public;
- internal = src/engine/<key>/internal;
- public/index.ts existe;
- contract declarado existe;
- token declarado existe;
- plugin declarado existe;
- native/tests/extra files declarados existem.
